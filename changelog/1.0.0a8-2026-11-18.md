# Aurora MVC 1.0.0a8 — 18 November 2026

Alpha 8 brings the Aurora Rebirth improvements into the published package for real-world developer testing in Milestone 7.

## Added

- Select a configured database for a generated model with `aurora model add NAME --database DATABASE`.
- Inspect verified backup history with `aurora db history --backups`.
- Review supported forward-only SQLite, MySQL, and PostgreSQL schema changes, including eligible foreign keys, UNIQUE constraints, indexes, explicit renames, and guarded table or column removal.
- Organize managed snapshots and backups by database under `__migrations__/` and `__backups__/`.

## Changed

- Configure one project `default_database` alongside separate database and model manifests; generated MVC projects use a `data` SQLite database by default.
- Keep backups optional and developer-initiated; potentially destructive migrations still require physical-state and dependency checks, explicit warnings, and acknowledgment.
- Coordinate supported combinations of ordinary server-column changes in a single reviewed forward migration.
- Associate migration history and backup records with the selected database identity; restore execution remains disabled.
- Refresh CLI, configuration, database, and developer documentation to reflect supported workflows.

## Fixed

- Improve duplicate-model registration refusal before creating a generated model file.
- Refuse unsafe SQLite index removal when the target index is missing, unrelated, or constraint-owned.
- Distinguish MySQL pre-DDL failures from uncertain outcomes after DDL begins in guarded table removal.
- Align packaging metadata, README generation, CI release checks, and async-test configuration with the accepted release workflow.

## Retired

- Retire obsolete legacy tests after preserving essential authentication-guard and safety coverage in the active suite.
- Retire obsolete public migration options and automatic migration-time backups; standalone `aurora db backup` remains available.

## Scope

- Migrations remain forward-only with backend-specific supported operations, not unrestricted DDL parity.
- `aurora db restore` remains disabled; backups are not proof of restoration capability.
- Alpha 8 is intended for evaluation and Milestone 7 real-world application acceptance, not production certification.
